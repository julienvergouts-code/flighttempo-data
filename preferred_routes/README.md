# Route intelligence: preferred routes and generated candidates

FlightTempo keeps two related but separate layers:

1. **Navigation infrastructure** — airports, runways, fixes, navaids, airway segments and published procedures, each with source/cycle/licence metadata.
2. **Route intelligence** — route candidates and recurring route patterns built from the navigation graph, permitted public route examples, and ADS-B observations.

## Key distinction

A route generated by FlightTempo is a **generated candidate**, not a filed flight plan. An ADS-B trajectory is an **observed flown route**, not proof of the filed route or ATC clearance. A route from an authorised flight-plan feed may be labelled **public_filed_route** only when the source actually supplies filed-route data and its use is permitted.

## How route intelligence grows

- The route engine generates one or more paths between airport connectors using existing airway graph edges and constraints.
- Save the exact waypoint sequence and airway legs as a generated candidate, with graph/source version, generation time, direction, requested flight level and route cost.
- Repeated generated candidates can be clustered by city pair and directional corridor.
- ADS-B tracks are independently map-matched against fixes and airway geometry. They add observed-route evidence, not airway publication status.
- Publicly available filed-route examples, where licensing permits, are stored with their own source classification.
- Unknown fixes or links go into an evidence queue. They are never silently inserted into the authoritative navigation graph.
- Promote a navigation record only after independent source validation and licence review.

## Route record fields

Each route record should contain routeId, origin, destination, direction, routeClass, status, ordered waypoints and airwayLegs, source URI/name, retrieval or generation timestamp, licence, navigation graph version / AIRAC cycle where applicable, flight level and constraints, observation count, first/last dates, confidence and validation notes where applicable.

## Current implementation status

The schema and empty dataset establish the storage contract. The existing A* graph remains the route generator; this repository change does not claim to have run a new route generation job. The next integration step is to have the Android/app route engine or a reproducible graph-build job export its chosen paths into this schema.

## Data access

EUROCONTROL NM B2B and FAA SWIM are possible restricted/authorised sources for actual filed flight data. Do not label any generated route as filed. OpenSky and ADS-B sources provide observed positions/tracks, not public filed OFPs. Access and redistribution terms must be checked per provider.

No AIP ingestion is introduced by this subsystem. No proprietary commercial navdata is used.
